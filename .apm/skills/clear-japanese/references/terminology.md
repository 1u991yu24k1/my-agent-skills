# 用語の導入ルール

読者は, この文書以外の文脈を持たない前提で書く.
読者が出所を追えない語は, すべて未定義語として扱う.

## 語の種類と書き方

| 種類 | 書き方 | 例 |
|------|--------|-----|
| 実在の識別子 | バッククォートで囲む. 前後に空白を1文字置く | `tracepoint_synchronize_unregister()` |
| 一般的な技術用語 | 初出で日本語の説明を添える. 英語表記は括弧に入れる | ページテーブル(page table) |
| 略語 | 初出で正式名称と意味を書く | TLB(変換結果のキャッシュ) |
| 文書内で定義する語 | 初出で定義文を書く. 以降は同じ表記で通す | 本書で `待機解除` は, ...を指す |
| 造語, 作業中のあだ名 | 使わない. 実在の識別子か日本語の説明に置き換える | 禁止 |

## 守ること

1. 識別子を指すときは, コードに存在する名前をそのまま書く.
   読者がコードと突き合わせられる状態にする.
2. 英語の名詞を地の文に混ぜて圧縮しない.
   `online flag を落とす` ではなく,
   `probes[i].registered` をクリアする, と書く.
3. 英単語に `する` を付けて動詞にしない(`drop する`, `emit される`).
   実在の関数名か, 日本語の動詞を使う.
4. 一般語(`transaction`, `registry`, `generation`, `shape`)を
   文書内の特殊な意味で使うなら, 初出で定義する.
   定義がなければ, 別の文脈の意味に取られる.
5. 一つの概念に一つの表記を割り当てる.
   `ページ` と `page` と `ページフレーム` を混在させない.
6. 外来語や英語ジャーゴン(`fail-closed`, `authoritative`)は,
   初出で日本語に言い換えて意味を書く.

## 定義文の型

```
X とは, <上位概念>のうち<条件>であるものを指す.
本書では <実在の識別子や処理> に対応する.
```

## 書く前の確認

- この語を, 前提知識のない同僚に説明できるか.
- この語は, コードのどの名前に対応するか.
- 対応が無ければ, 日本語の説明で書き直したか.
