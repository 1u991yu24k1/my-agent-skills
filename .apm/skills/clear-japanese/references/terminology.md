# 用語の導入ルール

読者は, この文書以外の文脈を持たない前提で書く.
読者が出所を追えない語は, すべて未定義語として扱う.

## 語の種類と書き方

| 種類 | 書き方 | 例 |
|------|--------|-----|
| 実在の識別子 | バッククォートで囲む. 前後に空白を1文字置く | `tracepoint_synchronize_unregister()` |
| 一般的な技術用語 | 初出で日本語の説明を添える. 英語表記は括弧に入れる | ページテーブル(page table) |
| 略語 | 初出で正式名称と意味を書く | TLB(変換結果のキャッシュ) |
| 文書内で定義する語 | 初出で定義文を書く. 以降は同じ表記で通す | 本書で `待機解除` は, ...を指す |
| 造語, 作業中のあだ名 | 使わない. 実在の識別子か日本語の説明に置き換える | 禁止 |

## 守ること

1. 識別子を指すときは, コードに存在する名前をそのまま書く.
   読者がコードと突き合わせられる状態にする.
2. 英語の名詞を地の文に混ぜて圧縮しない.
   `online flag を落とす` ではなく,
   `probes[i].registered` をクリアする, と書く.
3. 英単語に `する` を付けて動詞にしない(`drop する`, `emit される`).
   実在の関数名か, 日本語の動詞を使う.
4. 一般語(`transaction`, `registry`, `generation`, `shape`)を
   文書内の特殊な意味で使うなら, 初出で定義する.
   定義がなければ, 別の文脈の意味に取られる.
5. 一つの概念に一つの表記を割り当てる.
   `ページ` と `page` と `ページフレーム` を混在させない.
6. 外来語や英語ジャーゴン(`fail-closed`, `authoritative`)は,
   初出で日本語に言い換えて意味を書く.

## 定義文の型

```
X とは, <上位概念>のうち<条件>であるものを指す.
本書では <実在の識別子や処理> に対応する.
```

## 書く前の確認

- この語を, 前提知識のない同僚に説明できるか.
- この語は, コードのどの名前に対応するか.
- 対応が無ければ, 日本語の説明で書き直したか.

## 英語の扱い

地の文は日本語で書く. 英語は, 次の表の範囲に限る.

| 区分 | 扱い | 例 |
|------|------|-----|
| 識別子 | バッククォートで囲む | `rb_node`, `tasks_timeline` |
| 略語 | 初出で正式名称と意味を書く. 大文字のまま書く | TLB, RCU, UAF |
| 固有名詞 | そのまま書く | Linux, Rust, Kconfig |
| 日本語として定着した語 | カタカナで書く | キャッシュ, ポインタ, ロック |
| 上記以外の英単語 | 地の文に書かない. 日本語に直す | `bucket` を `バケット` に |

日本語に空白なしで接した英単語 (`bucket番号`, `cacheし`) は書かない.
`lint_ja.py` は, この接着と, 英単語の密度を FAIL にする.

## 推奨する日本語

初出で意味を書き, 以降は同じ表記で通す.

| 英語 | 日本語 | 初出で添える説明 |
|------|--------|------------------|
| bucket | バケット | ハッシュ値で選ぶ, 要素の入れ物 |
| slot | スロット | 配列の1要素分の置き場 |
| cache | キャッシュ | 結果を保存しておく領域 |
| lookup | 検索 | キーに対応する要素を探す操作 |
| intrusive | 埋め込み型 | 要素自身がノードをメンバに持つ方式 |
| uncle | 叔父ノード | 親の兄弟のノード |
| augmentation | 付加情報 | 各ノードに追加で持たせる集計値 |
| wrapper | ラッパー | 元の型を包んで安全な操作だけを出す型 |
| rollback | 巻き戻し | 失敗時に途中までの変更を取り消す処理 |
| payload | 格納する値 | 木や表が運ぶ本体のデータ |
| tail latency | 最悪側の遅延 | 遅い側の少数の処理にかかる時間 |
| canonical | 正規形 | x86-64 で上位16 bit が bit 47 の符号拡張になっているアドレス |
| writer, reader | 書き込み側, 読み取り側 | 構造を更新する処理, 参照する処理 |

## 用語表

新語を5語以上導入する文書は, 冒頭に用語表を置く.
表は, 語, 意味, 対応するコードの名前の3列にする.
