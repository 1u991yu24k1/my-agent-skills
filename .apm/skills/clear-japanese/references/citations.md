# 引用と出典の書き方

引用とは, 主張の根拠を, 読者が原典で確かめられる形で示すことである.
本ページは, 版と取得元, ソースコードの抜粋, 注釈コメント, 出典の書式, 引用と要約の区別を定める.
抜粋の行範囲, 長さ, 注釈の有無は `check_excerpt.py` で検査する.

## 版と取得元

1. 冒頭の1行に, 対象の版と取得元を書く. 書式は `対象: Linux 7.2.8, x86-64` である.
2. 本文はローカルの絶対パスを含めず, ツリーの場所は frontmatter の `source_tree:` に置く.
3. 草稿の状態は frontmatter の `status: draft` で示す. 本文では, 未ビルドなどの断りを1回にとどめる.
4. 実行結果の扱いは, 検証記録のページに従う.

frontmatter は次の形で書く.

```yaml
source_version: "linux-7.2.8"
source_tree: /path/to/linux-7.2.8
status: draft
```

## 抜粋の3点

ソースコードの抜粋は, 前の文, 抜粋, 後の文の3点で示す.

| 位置 | 書くこと |
|------|----------|
| 抜粋の前 | 版, `パス:行範囲`, 読む目的(この抜粋で答える問い) |
| 抜粋 | 問いに答える行, 読む点の注釈, 省略の明示 |
| 抜粋の後 | 抜粋のどの行が, 主張のどの部分を示すか |

## 抜粋の範囲

1. 構造体は, 名前と概要だけで済ませず, 理解に必要な実際の定義を抜粋する.
2. 節の疑問に答える範囲を選ぶ. 関数の全文を転載せず, 答える範囲に絞る.
3. 1つの抜粋は30行を目安にする. 超えるときは, 問いごとに抜粋を分ける.
4. 関数の全文が必要なら, 付録に置くか, 版を固定した URL へのリンクにする.
5. 省略した範囲は, `/* 省略: 縮小時のエラー処理 */` のように内容を書く.
6. 実コードの提示では, 説明用の疑似コードに置き換えた箇所を明記する.
7. 書き手が書いたコード(説明用のコード, 攻撃コード)は, 抜粋の前の文でその旨を書く.

## 注釈コメント

注釈コメントには, コードを読むだけでは分からない情報を書く.

| 書く内容 | 例 |
|----------|----|
| 状態 | `/* ここで buf->len は 200 になる */` |
| 意図 | `/* 次の書き込みが同じページに追記できるようにする */` |
| 不変条件 | `/* head - tail は常に max_usage 以下 */` |
| 本文との対応 | `/* (1) 本文の手順1 */` |

1. 読むべき点に, 日本語の注釈を付ける. コードの言い換え(`i++; /* i を増やす */`)は書かない.
2. 本文から参照する行には `/* (1) */` のような番号を付け, 本文で `(1) の行で` と参照する.
3. 実コードの英語のコメントは原文のまま残す. 書き手が足す注釈は日本語で書き, 原文のコメントと区別する.
4. 誤解しやすい操作は, 変更する対象と引き継ぐ対象を具体的に書く.
   例: 配列は再確保するが, データページは参照を引き継ぐ.

注釈を付けた抜粋の全体の例は, `references/good_examples.md` の例7にある.

## 出典の書式

出所の種類ごとに, 次の情報を書く.

| 出所 | 書く情報 | 例 |
|------|----------|----|
| ソースコード | 版, `パス:行`, 検索語 | `fs/pipe.c:523` (`^anon_pipe_write`), Linux 7.2.8 |
| 公開リポジトリ | commit を固定した URL | `https://github.com/<org>/<repo>/blob/<commit>/<path>#L10-L20` |
| 論文 | 著者, 題名, 会議か誌, 年, 本文の位置 | 3.2 節, 図4, 表2, 式(5) |
| Web の文書 | 題名, URL, 版か参照日 | `参照日: 2026-11-15` |
| commit, メーリングリスト | hash の先頭12桁, 件名, URL | `0123456789ab ("pipe: ...")` |
| 実行結果 | コマンド, 環境 | `環境: Ubuntu 24.04, x86-64` |

1. ブランチ名を含む URL(`blob/master/`)は, 内容が変わるので使わない. commit を固定する.
2. 行番号は版に固定した値である. 行番号と一緒に, 検索できる語を併記する.
3. 定義位置, 呼び出し位置, マクロの生成元を区別して書く. 経路図では `def`, `call`, `gen` のマーカーで区別する.

## 出典の置き場所

1. 出典は, 主張と同じ節に置く. 読者が主張を読んだ位置で, 根拠を確かめられるようにする.
2. 経路図がある節では, 出典を経路図のコメントに一本化する. 図の直後の箇条書きで, 同じ行番号を繰り返す必要はない.
3. 末尾の表には, 図に出ない定義だけを載せる.

| ソース位置 | 検索語 | 確認する内容 |
|------------|--------|--------------|
| `include/linux/pipe_fs_i.h:26` | `^struct pipe_buffer` | ページを指す配列の要素 |

## 末尾の参照節

- 参照節は, `一次ソース`, `関連` のように役割ごとに1節ずつ置く.
- 同じ内容を指す節を, 複数の見出しで重複させない.
- 参照節の分量は, 本文より短くする.
- 作業の経緯や検証の状況は, 参照節にも書かず, 検証記録のページに置く.

## 引用と要約の区別

1. 原文をそのまま引くときは, `>` の引用にし, 直後に出典を書く.
2. 英語の原文を訳したときは, 訳であることと, 原文の位置を書く.
3. 要約と解釈は地の文で書く. 原文の主張(`論文は〜と報告する`)と, 書き手の解釈(`この結果から〜と考えられる`)を, 文末で書き分ける.
4. 数値は原文のまま書き, 出典の位置(表の番号など)を添える. 丸めたときは, 丸めたことを書く.
