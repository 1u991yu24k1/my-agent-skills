# CTF writeup

CTF writeup とは, CTF の問題を解いた過程と攻撃手法を, 第三者が再現できるように説明する記事である.
本ページは, writeup の説明の順序, 図, 抜粋の規則を定める.
記事に含める必須の内容(問題の情報, 解析結果, 最終の攻撃コード, フラグ)とファイル名は, `ctf-writeup-skill` に従う.

## 用語

CTF で定着した語はカタカナで書き, 初出で意味を添える.

| 語 | 初出で添える説明 |
|----|------------------|
| エクスプロイト | 脆弱性を使って目標(フラグの取得, 権限の昇格)を達成するコード |
| プリミティブ | 脆弱性から得る基本操作. 任意のアドレスへの書き込みなど |
| 緩和策 | 攻撃を難しくする防御機構. ASLR, NX, スタックカナリアなど |
| PoC | 脆弱性が発火することを示す最小の入力やコード |
| ガジェット | ROP(戻り先の連鎖で命令列を実行する手法)で使う, `ret` で終わる短い命令列 |

## 6要素との対応

設計の6要素は, writeup では次の内容に対応する.

| 要素 | writeup での内容 |
|------|------------------|
| 課題 | フラグの取得, 権限の昇格, サンドボックスからの脱出 |
| 制約 | 緩和策, 実行環境, 入力の制限 |
| 方針 | プリミティブの連鎖 |
| 結論 | 最終のエクスプロイト |
| 根拠 | 実行結果, デバッガの出力 |
| 代償 | 成功率, 前提条件 |

## 骨格

writeup は, 次の順に節を置く.

| 順 | 節 | 内容 |
|----|----|------|
| 1 | 概要 | 問題の名前とカテゴリ, 脆弱性の種類, 攻撃の方針を3行で書く |
| 2 | 解析 | 観察した事実, 根本原因, 脆弱性を発火させる最小の PoC |
| 3 | 攻撃の方針 | 目標, 制約(緩和策), プリミティブの連鎖 |
| 4 | 実装 | 方針の各段階に対応する抜粋と, 実行結果 |
| 5 | フラグ | 取得したフラグ. 取得していなければ, その旨 |
| 6 | 知見 | 他の問題に使える手法, 判断の分かれ目 |
| 付録 | 最終のエクスプロイト | 全文 |

## 固有の規則

1. 概要の3行で, 読者が結論(何の脆弱性を, どう使ったか)を知れるようにする.
2. 解析は, 観察, 仮説, 確認の順に書く. 根本原因は, 該当するコードの抜粋と, 最小の PoC で示す.
3. 方針を組み立てた過程は, 採った案と捨てた案を並べ, 判断の理由として書く. 時系列の日記は, 判断の理由を埋もれさせる.

   ```
   悪い例: 最初は __free_hook を書き換えようとしたが, 動かなかった.
           調べたところ, 新しい glibc には無かった. そこで別の方法を探した.
   良い例: `__free_hook` を書き換える案は, glibc 2.34 で `__free_hook` が削除されたので捨てた.
           代わりに `_IO_2_1_stdout_` を書き換え, ファイル構造体の関数表から `system` を呼ぶ方針を採った.
   ```
4. オフセットとアドレスは, 求め方を示す. デバッガの出力か計算式を併記し, 由来の分からない数値を残さない.
5. エクスプロイトの全文は付録に置く. 本文では, 方針の各段階に対応する部分を抜粋し, 段階の番号を注釈で付ける. 抜粋の規則は `references/citations.md` に従う.
6. プリミティブの連鎖は, 段階, 得る操作, 手段の3列の表で示す. 分岐がある場合だけ mermaid を使う.
7. ヒープやスタックの状態は, `references/memory-layout.md` の状態変化の図で, 操作の前後を示す.
8. 実行結果は貼り付ける. 成功率が100%でなければ, 試行回数と成功回数を書く.

プリミティブの連鎖の表は, 次の形で書く.

| 段階 | 得る操作 | 手段 |
|------|----------|------|
| 1 | ヒープの範囲外書き込み | `edit()` の長さ検査の欠落 |
| 2 | libc とヒープのアドレスの漏洩 | 解放済みチャンクに残る `fd` の読み出し |
| 3 | 任意のアドレスへの書き込み | `tcache` の `next` の書き換え |
| 4 | `system("/bin/sh")` の呼び出し | `_IO_2_1_stdout_` の書き換え |

表の各段階は, 実装の節の抜粋の注釈番号と対応させる.

## 検査

次のコマンドで, 表記, 骨格, 図, 抜粋を検査する.

```
python3 <skill>/scripts/check_doc.py <file> --genre writeup
```

`outline_ja.py` は, フラグの記述が無いときに INFO を出す.
