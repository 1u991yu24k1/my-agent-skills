# 論文の解説

論文の解説とは, 既存の学術論文を読み, その課題, 提案, 評価を, 原文を読んでいない読者に日本語で説明する文書である.
本ページは, 解説の骨格と, 論文の主張と解説者の解釈を書き分ける規則を定める.
本ページの対象は解説であり, 論文の執筆は対象外である.

## 6要素との対応

設計の6要素は, 論文の解説では次の内容に対応する.

| 要素 | 論文の解説での内容 |
|------|--------------------|
| 課題 | 研究課題. 何が解けていないか |
| 制約 | 既存手法の限界, 前提とする脅威モデルや計算資源 |
| 方針 | 提案の核心となる考え方 |
| 結論 | 主な結果 |
| 根拠 | 評価の表と図, 証明 |
| 代償 | 論文が認める限界, 評価していない条件 |

## 骨格

論文の解説は, 次の順に節を置く.

| 順 | 節 | 内容 |
|----|----|------|
| 0 | 書誌 | 著者, 題名, 会議か誌, 年, DOI か arXiv の番号 |
| 1 | 一文要約 | 何を解き, 何を示したかを1文で書く |
| 2 | 課題 | 研究課題と, 既存手法が解けない理由 |
| 3 | 提案の核心 | 考え方を1文で書き, 最小の例で示す |
| 4 | 手法 | 構成要素と, 各要素の役割 |
| 5 | 評価 | 何と比べ, どの条件で, 何が言えて何が言えないか |
| 6 | 限界と考察 | 論文が認める限界と, 解説者の考察を分けて書く |

## 主張と解釈の書き分け

1. 論文の主張は, 主語を論文か著者にする. `論文は, 〜と報告する`, `著者らは, 〜と主張する` と書く.
2. 解説者の解釈は, 推論であることを文末で示す. `〜と考えられる`, `解説者の解釈では` と書く.
3. 論文の慎重な言い方(示唆する, 可能性がある)と断定(示す, である)は, 原文の強さのまま書く.
4. 論文の主張と解説者の解釈は, 別の段落に書く.

## 数値, 式, 図

1. 数値は原文のまま書き, 表と図の番号を付ける(`表3 によると, 平均の遅延は 12.4 ms である`).
2. 評価の数値は, 比較の相手と条件(データセット, 環境)を同じ文に書く.
3. 式は, 記号の定義を式の直前に書く. 式の後に, 式が何を表すかを1文で書く.
4. 論文の図は転載せず, 必要な要素だけで再構成する. 元の図番号を書く.
5. 評価の節では, 論文の評価から言えることを先に書く. 言えないことは `>` の注意書きにまとめる.

## 用語

1. 論文の用語は, 初出で日本語の訳と原語を書く. 例えば `帰納的不変条件(inductive invariant)` と書く.
2. 新語を5語以上導入するなら, 冒頭に用語表を置く. 列は, 訳語, 原語, 意味にする.
3. 論文が独自に名付けた手法名は, 固有名詞としてそのまま書く.

## 修正例

悪い出力:

```
本論文は新しい手法 X を提案し, 既存手法より大幅に高速であることを示した.
X は実用的であり, 今後広く使われるだろう.
```

修正後:

```
論文は, 手法 X が既存手法 Y より平均で 2.1 倍速いと報告する(表3, 10 個の評価用プログラム).
最も効果が小さいプログラムでは, 1.1 倍である.

評価は x86-64 の1機種だけで行われている.
他の CPU でも同じ傾向になるかは, この評価からは判断できない.
```

直した点:

- 大幅に, を表の番号つきの数値と比較の相手に置き換えた.
- 解説者の予想(広く使われるだろう)を削り, 評価から言えない範囲を別の段落に分けた.

## 検査

次のコマンドで, 表記, 骨格, 図を検査する.

```
python3 <skill>/scripts/check_doc.py <file> --genre paper
```

`outline_ja.py` は, 冒頭に書誌情報(DOI か URL と, 年)が無いときに INFO を出す.
