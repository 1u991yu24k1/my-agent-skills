## 例1: Huge Page の導入(D1, D2 の修正)

悪い出力:

```
通常の x86-64 ページは 4 KiB だが, 多数のページを扱うと変換情報も大量に必要になる.
より大きな単位で対応付ければ, ページテーブルや TLB の負担を減らせる.
そのための Huge Page には, 明示的に使う HugeTLB と,
条件に応じて大きなページを使う THP がある.
両者は確保方法と失敗時の挙動が異なる.
```

修正後:

```
## Huge Page

Huge Page は, 1つの対応付けでカバーするメモリの範囲を広げ,
ページテーブルと TLB の消費を減らす仕組みである.
Linux には, 明示的に確保する HugeTLB と,
カーネルが自動で割り当てる THP の2方式がある.

### 通常のページで消費が増える理由

x86-64 の通常のページは 4 KiB である.
仮想アドレスを物理アドレスに変換するには,
ページごとにページテーブルエントリ(PTE)が1つ必要になる.
1 GiB を通常のページで対応付けると 262144 個の PTE が要り,
PTE が 8 バイトなら 2 MiB のメモリを消費する.

TLB は, この変換結果を保持するキャッシュで, エントリ数が限られる.
通常のページでは 1 エントリが 4 KiB しか表せないので,
広い範囲にアクセスすると TLB ミスが増える.
2 MiB のページなら, 1 エントリで 512 倍の範囲を表せる.

### HugeTLB と THP の違い

HugeTLB は, 事前に予約したプールから確保する.
プールが足りないと確保に失敗する.
THP は, 条件が合うときにカーネルが自動で割り当て,
合わなければ通常のページを使い続ける.

> 通常のページには, 割り当ての粒度が細かく, メモリの無駄が少ない利点がある.
```

直した点:

- 結論を最初に置き, 結論に出てくる語(PTE, TLB)を理由の段で定義した.
- 小さいページの欠点を理由として示し, 補足は最後に回した.
- 予告だけだった違いを, 同じ段で具体的に書いた.

## 例3: 赤黒木の導入(K1, T5, X1, E1 の修正)

悪い出力(元のノートの冒頭):

```
赤黒木は, 二分探索木の高さを色の制約で O(log n) に抑える.
挿入と削除の際に再着色と回転を行うため,
ソート済みキーの連続挿入でも単なる鎖に退化しない.

- 赤ノードの子は黒.
- 各ノードから NULL leaf までの黒ノード数が等しい.
```

修正後:

```
# 赤黒木

赤黒木は, 各ノードに赤か黒の色を持たせて, 木の高さを要素数の対数に抑える二分探索木である.
Linux では, タイマーの期限順の管理や, 次に実行するタスクの選択に使う.
前提知識は, 二分探索木の検索と, C のポインタである.
本ページは, 木の仕組みと `rb_node` の使い方を説明する. ロックによる保護は扱わない.

## 二分探索木が偏る問題

二分探索木は, 小さいキーを左に, 大きいキーを右に置く.
1, 2, 3 の順に挿入すると, すべての要素が右に連なり, 高さが 3 になる.
n 個を昇順に挿入すると高さが n になり, 検索に n 回の比較が必要になる.

## 色の規則が高さを抑える理由

赤黒木は, 次の3つの規則を保つ.

1. 根と葉(要素のない `NULL`)は黒である.
2. 赤ノードの子は, 必ず黒である.
3. 各ノードから葉までのどの経路にも, 同じ数の黒ノードがある.

規則3から, 経路ごとの黒ノードの数は等しい.
規則2から, 赤ノードは連続しないので, 1本の経路の赤ノードは黒ノード以下の数になる.
そのため最長の経路は, 最短の経路の2倍以下である.
n 個のノードの高さは 2 log2(n+1) 以下になり, 検索, 挿入, 削除は `O(log n)` で終わる.

## 3要素を昇順に挿入する例

1, 2, 3 を順に挿入する.

1. 1 を挿入する. 1 は根なので黒にする.
2. 2 を 1 の右の子として挿入し, 赤にする. 規則は破れない.
3. 3 を 2 の右の子として挿入し, 赤にする. 赤の 2 の子が赤になり, 規則2が破れる.
4. 3 の叔父ノード(親 2 の兄弟, つまり 1 の左の葉)は黒である.
   この場合は, 1 を軸に左回転する. 2 が根になり, 1 と 3 がその子になる.
5. 2 を黒に, 1 と 3 を赤にする. 高さは 2 になり, 規則がすべて成り立つ.
```

直した点:

- 体言止め(`赤ノードの子は黒.`)を, 述語のある文にした.
- `O(log n)` に収まる理由を, 3つの規則から導いて同じ節に書いた.
- `uncle` と `leaf` を, 叔父ノード(親の兄弟)と葉に直し, 初出で意味を添えた.
- API の表より先に, 3要素の挿入例を手で追える形で示した.
