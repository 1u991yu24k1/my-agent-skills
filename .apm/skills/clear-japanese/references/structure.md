# 文書の構成

## 基本構成

結論, 理由, 例, 補足 の順に書く.
長い文書に限り, 末尾に結論を再掲する.

| 段 | 内容 | 注意 |
|----|------|------|
| 結論 | 主張を1から2文で書く | 理由が必要な語は, ここで使わず理由で説明する |
| 理由 | 結論が成り立つ根拠 | 結論で生じた疑問に, この段で答える |
| 例 | 具体的な値, コード, 手順 | コードの前に目的を書く |
| 補足 | 例外, 制限, 対比 | 理由より後ろに置く. 注意書きは `>` を使う |
| 再掲 | 判断基準や次の行動 | 条件を満たすときだけ書く |

## 結論の再掲

次の全てを満たすときだけ書く.

- 3節以上の文書, または結論から末尾まで長い回答である.
- 判断基準や次の行動など, 新しい情報を1文以上含められる.

短い会話の回答には付けない. 言い換えだけの総括は書かない.

## 談話の規則

1. 文が疑問を生んだら, 次の文でその疑問に答える.
   `変換情報が大量に必要になる` と書いたら, 直後で変換情報とは何か,
   なぜページ数に比例するかを書く.
2. 対比と補足は, 理由を述べ終えた後に置く.
3. `両者は異なる` のように, 中身のない予告文で終えない.
   違いを同じ段で書く.
4. 隣接する二文の関係(理由, 具体化, 対比, 補足)を説明できなければ,
   接続詞を足すか, 文を並べ替える.
5. 箇条書きに項目間の因果や対比があるなら, 文で書く.

## 見出し

1. 見出しは内容を予告する名詞句にする.
   結論の一部を命題にしない.
2. H1 の主題語を, 冒頭の定義文と節の見出しに引き継ぐ.
   主題と無関係な節は, 冒頭で主題との関係を書く.
3. 1節は2段落以上を目安にする. 1文だけの節を作らない.

## ページ冒頭に置く3点

1. 主題の定義. スケジューラなら, CPU 数より実行可能なタスクが
   多いときに, どのタスクをどの CPU で動かすかを決める処理, と書く
2. このページで扱う範囲, 扱わない範囲
3. 節の一覧(長い文書のみ)

## 文書種別ごとの構成

| 種別 | 構成 |
|------|------|
| 回答 | 結論, 根拠, 必要な但し書き |
| 解説 | 定義, 全体像, 詳細, 例, 補足 |
| 調査報告 | 結論, 観測した事実, 推論, 未確認事項 |
| 設計説明 | 目的, 構成, 各部の責務, 選択肢と判断理由 |
| レビュー | 重大度順の指摘, 各指摘に場所と再現条件 |
| writeup | 概要, 脆弱性, 利用手順, 検証 |
