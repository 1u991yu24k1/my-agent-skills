# メモリ配置図の表記

メモリ配置図は, 枠と文字の位置から, 領域の境界とポインタの参照先を読み取る図である.
図内は ASCII 文字だけで構成し, 文字幅による境界のずれを防ぐ.
図外の説明では通常の日本語を使う.

## 作図時の規則

- 枠, 区画内の文字, 矢印, 矢印のラベルは ASCII にする.
- 枠線は `+`, `-`, `|`, 矢印は `-->`, `<--`, `<-->` などで描く.
- タブを使わず, 空白で位置をそろえる.
- 図内は実在の識別子, 数値, 単位, 短い英語ラベルを使う.
- 日本語の説明は図の前後へ置く. 対応先は `A0`, `B1` などの記号や, 枠外へ伸ばした矢印で識別する.
- 日本語を含むインラインコードは使ってよい. 図のコードフェンス内へ日本語を戻す用途では使わない.
- 配列のポインタと参照先の実体を分ける. 矢印は参照関係, 横並びの区画は同じ領域内の配置に使う.
- 概念図には省略範囲と版を図外で示す. 世代の異なる構造体を一枚の現行配置図へ混在させない.

Mermaid でメモリ配置や対応する確保フローを描く場合も, ノード内と辺のラベルを ASCII にする.
英語ラベルの意味は図外で日本語にする.
通常の日本語本文には `clear-japanese` の文体規則を適用し, 図内の短い英語ラベルは例外として扱う.

## 作図の設計規則

1. 1つの図で伝える内容を1文で決める. 図の領域は8個までにし, 超えたら図を分ける.
2. アドレスは, 低位ほど上に書く. 縦に並べる図は, 上から下へアドレスが増える向きに固定する.
   横に並べる図に限り, 左を低位にする.
   向きは, 図の前の1文で読者に伝える.
3. 1行は80桁以内にする. 超える図は, 部分ごとに分ける.
4. 構造体の配置図は, 区画の左に `offset` と `size` を数値と単位で書く.
   - 進数は図内で統一する. 全体のサイズは, 最後の区画の下に終端として書く.
   - 詰め物(パディング)も区画として描き, `(padding)` と書く.
5. 区画の高さと幅は, 実サイズに比例させない. 大きさは数値で読ませる.
6. 線の意味を固定する. 1つの図の中で意味を変えない.

   | 表記 | 意味 |
   |------|------|
   | `-->` | セルの値が指す先 (ポインタの参照) |
   | `<-->` | 双方向のリンク (前後のポインタ) |
   | 枠の隣接, 入れ子 | 同じ領域内の配置, 包含 |

7. 図の直後に, 凡例を表で書く. 列は, 記号, 意味, 対応する識別子の3つにする.
8. 枠の `+` と `|` は同じ列にそろえる. 行末に空白を残さない.

## 例 1: 構造体のオフセットとパディング

構造体の各メンバが先頭から何バイト目にあるかを示す, 最小の例である.
次の構造体を, x86-64 で配置する.

```c
struct sample {
    char tag;
    int count;
    void *next;
};
```

`count` は 4 バイト境界, `next` は 8 バイト境界に置く必要がある.
そのため `tag` の後に 3 バイトの詰め物が入り, 全体は 16 バイトになる.
低位アドレスを上に置く.

```text
offset  size  field
              +--------------------+
   0    1 B   | tag                |
              +--------------------+
   1    3 B   | (padding)          |
              +--------------------+
   4    4 B   | count              |
              +--------------------+
   8    8 B   | next               |
              +--------------------+
  16    (end)
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `offset` | 構造体の先頭からのバイト数 | `offsetof(struct sample, count)` |
| `size` | 区画のバイト数 | `sizeof(((struct sample *)0)->count)` |
| `(padding)` | 配置の都合で空く領域 | なし |

## 例 2: 連結リストとポインタ

3つのノードが別々のアドレスにあり, ポインタでつながる様子を示す.
`next` のセルには, 次のノードの先頭アドレスが入っている.
矢印は, そのアドレスが指す先を表す. 最後のノードの `next` は `NULL` である.
横に並べ, 左を低位アドレスとして読む.

```text
head         node A @0x1000     node B @0x2040     node C @0x3080
+--------+   +-----+--------+   +-----+--------+   +-----+--------+
| 0x1000 |-->| 7   | 0x2040 |-->| 9   | 0x3080 |-->| 4   | NULL   |
+--------+   +-----+--------+   +-----+--------+   +-----+--------+
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `head` | 先頭ノードのアドレスを持つ変数 | リストの先頭ポインタ |
| 左のセル (7, 9, 4) | ノードが持つ値 | 各ノードの値のメンバ |
| 右のセル | 次のノードのアドレス | 各ノードの `next` メンバ |


## 例 3: パイプの配列とページ

管理配列と実データを別領域に描き, ページ内の有効範囲を数値で示す例である.
`consumed` は読み取り済み, `valid` は読み取り可能, `unused` は未使用を表す.

```text

  head = 2, tail = 0
  ring_size = 4
  bufs ----------------------+
  tmp_page[0..1]             |
                             v
pipe_buffer bufs[4]        struct page           Physical page (4096 B)
+---------------------+   +-------------+       +------------+-------------+
| [0] page -----------+-->| page A      |------>| consumed   | valid       |
| offset=1000         |   +-------------+       | 1000 B     | 3096 B      |
| len=3096            |                         +------------+-------------+
+---------------------+   +-------------+       0            1000       4096
| [1] page -----------+-->| page B      |------>+-----+--------+-----------+
| offset=0, len=1904  |   +-------------+       | valid        | unused    |
+---------------------+                         | 1904 B       |           |
| [2] next (head)     |                         +-----+--------+-----------+
+---------------------+                         0              1904     4096
| [3] free            |
+---------------------+
```

## 例 4: スラブのポインタ配列

sheaf が参照を保持し, オブジェクト本体は別の領域にあることを示す.
`M` は通常用, `S` は予備の sheaf であり, `N` は NUMA ノード番号である.

```text
kmem_cache
+-------------------------+
| cpu_sheaves -------------+--> [C0] CPU-local storage
| per_node[N].barn --------+--> [BN] Node-local barn
| per_node[N].node --------+--> [KN] Node-local slab management
+-------------------------+

[C0] CPU 0: slub_percpu_sheaves       slab_sheaf M (size = 2)
+--------------------------+        +-------------------------+
| main --------------------+------->| objects[0] = A0 ---------+--> [A0]
| spare -------------------+--+     | objects[1] = B1 ---------+--> [B1]
| rcu_free                 |  |     | objects[2..]            |
+--------------------------+  |     +-------------------------+
                              +---> slab_sheaf S

[BN] node_barn
+-------------------------+       +----------------+     +----------------+
| sheaves_full -----------+<----->| slab_sheaf F0  |<--->| slab_sheaf F1  |
| sheaves_empty ----------+--+    | barn_list      |     | barn_list      |
+-------------------------+  |    +----------------+     +----------------+
                             +<--> slab_sheaf E0 <--> ...

[KN] kmem_cache_node
+-------------------------+
| partial ----------------+----> slab with free objects <--> ...
+-------------------------+

Object storage (separate from pointer arrays):
  slab A:  +------+------+------+------+
           | A0   | A1   | A2   | ...  |
           +------+------+------+------+
  slab B:  +------+------+------+------+
           | B0   | B1   | B2   | ...  |
           +------+------+------+------+
```

## 例 5: スラブの空きリスト

従来の CPU 側のリストとスラブ側のリストを分ける例である.
`allocated` は呼び出し元が使用中の領域を表す.
この図は旧方式の参照関係を示す模式図である.

```text
kmem_cache
+-------------------+
| cpu_slab ---------+----> CPU 0: kmem_cache_cpu
| node[N] ----------+--+         +--------------------+
+-------------------+  |         | freelist ----------+----> A0 --> A2 --> NULL
                       |         | slab --------------+--+
                       |         | partial -----------+--|---> slab B --> ...
                       |         +--------------------+  |
                       |                                 v
                       |                        slab A (active)
                       |                        +--------------------+
                       |                        | freelist ----------+--> A3 --> NULL
                       |                        +--------------------+
                       v
               kmem_cache_node
               +--------------------+
               | partial -----------+----> slab C <--> slab D <--> ...
               +--------------------+

Example object storage in slab A:
  +----------------+----------------+----------------+----------------+
  | A0: CPU free   | A1: allocated  | A2: CPU free   | A3: slab free  |
  +----------------+----------------+----------------+----------------+

Free object A0                  Free object A2
+----------------------+        +----------------------+
| ...                  |        | ...                  |
| freepointer @ offset +------->| freepointer @ offset +----> NULL
| ...                  |        | ...                  |
+----------------------+        +----------------------+
```

## 検査

図のコードフェンスから本文を抽出し, `str.isascii()` で ASCII 文字だけであることを検査する.
併せてタブの混入, 枠の左右位置, 矢印の終点, 数値と本文の一致を目視で検査する.
ポインタの接続先とカーネル実装との対応は, ソースと照合して検査する.
