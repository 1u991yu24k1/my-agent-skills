# メモリ配置図と状態変化の表記

メモリ配置図は, 枠と文字の位置から, 領域の境界とポインタの参照先を読み取る図である.
状態変化の図は, 同じ構造の操作前と操作後を並べて, 値の推移を読み取る図である.
等幅の図は ASCII 文字だけで構成し, 文字幅による境界のずれを防ぐ.
図外の説明では通常の日本語を使う.

## 作図時の規則

- 枠, 区画内の文字, 矢印, 矢印のラベルは ASCII にする.
- 枠線は `+`, `-`, `|` で描く.
- タブを使わず, 空白で位置をそろえる.
- 日本語の説明は図の前後へ置く. 対応先は `PgA`, `[S0]` などの識別子で示す.
- 日本語を含むインラインコードは, 図の外の文でだけ使う.
- 配列のポインタと参照先の実体を分ける. 矢印は参照関係, 横並びの区画は同じ領域内の配置に使う.
- 概念図には省略範囲と版を図外で示す. 世代の異なる構造体を一枚の現行配置図へ混在させない.

### 図内の英語ラベル

図の中の英語は, 地の文を日本語にする規則の例外である. 例外は次の条件を満たすものに限る.

1. ラベルは, 実在の識別子か名詞句にする. 3語以内に収める.
2. 語句にとどめる. `No pages for empty slots` や `next loop iteration` のような文は避ける.
3. 使った語は, 図の直後の凡例表に載せる. 語彙は, ラベルの語彙の表から選ぶ.

Mermaid の図は等幅ではないので, ASCII の制限を受けない.
ノードと辺のラベルは日本語で書いてよい. 識別子とコードの断片は, そのまま書く.

## ラベルの語彙

同じ意味には同じ語を使う. 語を増やすときは, この表に追加する.

| ラベル | 意味 |
|--------|------|
| `empty` | 使っていない配列の要素 |
| `used`, `free` | 使用中のオブジェクト, 空いているオブジェクト |
| `valid` | ページ内の読み取り可能な範囲 |
| `consumed` | ページ内の読み取り済みの範囲 |
| `unused` | ページ内の未使用の範囲 |
| `head`, `tail` | リングの追加位置, 読み取り位置 |
| `off`, `len` | ページ内の開始位置, 有効バイト数 |
| `old`, `new` | 変更前の配列, 変更後の配列 |
| `src` | コピー元のユーザ空間のバッファ |
| `before`, `after` | 操作の前, 操作の後 (図の見出しだけに使う) |

## 作図の設計規則

1. 1つの図で伝える内容を1文で決める. 図の領域は8個までにし, 超えたら図を分ける.
2. アドレスは, 低位ほど上に書く. 縦に並べる図は, 上から下へアドレスが増える向きに固定する.
   横に並べる図に限り, 左を低位にする.
   向きは, 図の前の1文で読者に伝える.
3. 1行は80桁以内にする. 超える図は, 部分ごとに分ける.
4. 構造体の配置図は, 区画の左に `offset` と `size` を数値と単位で書く.
   - 進数は図内で統一する. 全体のサイズは, 最後の区画の下に終端として書く.
   - 詰め物(パディング)も区画として描き, `(padding)` と書く.
5. 区画の高さと幅は, 実サイズに比例させない. 大きさは数値で読ませる.
6. 線の意味を固定する. 1つの図の中では同じ意味で通す.

   | 表記 | 意味 |
   |------|------|
   | `-->`, `<--` | セルの値が指す先 (ポインタの参照) |
   | `<-->` | 双方向のリンク (前後のポインタ) |
   | `====>` | データのバイト列のコピー |
   | 枠の隣接, 入れ子 | 同じ領域内の配置, 包含 |

7. 図の直後に, 凡例を表で書く. 列は, 記号, 意味, 対応する識別子の3つにする.
8. 枠の `+` と `|` は同じ列にそろえる. 行末の空白は削る.
9. 識別子は系列ごとに接頭辞を分ける.
   - 図の見出しの状態は `[S0]`, `[S1]`, 容量変更の状態は `[C0]`, `[C1]` のように書く.
   - ページなどのオブジェクトは, 括弧なしの2文字以上で `PgA` のように書く.
   - 識別子は2文字以上にする. 1文字 (`A`, `B`) は別の用途と区別できない.
10. 矢印で `[S1]` などの識別子を指すなら, 同じ図の中に定義(見出しの `[S1]`)を置く.
11. 全体の参照関係を先に示してから, 個々の構造体の図へ進む.
12. リストなど横方向に追う対象は, 横長の配置にする.

### 状態変化の図

1. 操作前と操作後を, 同じ形式の2つの図で示す. 操作の内容は, 図の間の文で書く.
2. 同じオブジェクトには, 図をまたいで同じ識別子を使う.
3. 添字, 要素数, 有効範囲など, 変化を判断できる値を図の見出しと区画に入れる.
4. 確保, 再利用, データのコピー, 解放を区別する. 区別は図の間の文で書く.
5. 複数の図に分けても, 操作と値の推移を連続して追えるようにする.
   前の図の操作後の値と, 次の図の操作前の値は同じにする.
6. 時系列や主体間のやり取りは, Mermaid のシーケンス図で描く.

## 例 1: 構造体のオフセットとパディング

構造体の各メンバが先頭から何バイト目にあるかを示す, 最小の例である.
次の構造体を, x86-64 で配置する.

```c
struct sample {
    char tag;
    int count;
    void *next;
};
```

`count` は 4 バイト境界, `next` は 8 バイト境界に置く必要がある.
そのため `tag` の後に 3 バイトの詰め物が入り, 全体は 16 バイトになる.
低位アドレスを上に置く.

```text
offset  size  field
              +--------------------+
   0    1 B   | tag                |
              +--------------------+
   1    3 B   | (padding)          |
              +--------------------+
   4    4 B   | count              |
              +--------------------+
   8    8 B   | next               |
              +--------------------+
  16    (end)
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `offset` | 構造体の先頭からのバイト数 | `offsetof(struct sample, count)` |
| `size` | 区画のバイト数 | `sizeof(((struct sample *)0)->count)` |
| `(padding)` | 配置の都合で空く領域 | なし |

## 例 2: 連結リストとポインタ

3つのノードが別々のアドレスにあり, ポインタでつながる様子を示す.
`next` のセルには, 次のノードの先頭アドレスが入っている.
矢印は, そのアドレスが指す先を表す. 最後のノードの `next` は `NULL` である.
横に並べ, 左を低位アドレスとして読む.

```text
head         node A @0x1000     node B @0x2040     node C @0x3080
+--------+   +-----+--------+   +-----+--------+   +-----+--------+
| 0x1000 |-->| 7   | 0x2040 |-->| 9   | 0x3080 |-->| 4   | NULL   |
+--------+   +-----+--------+   +-----+--------+   +-----+--------+
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `head` | 先頭ノードのアドレスを持つ変数 | リストの先頭ポインタ |
| 左のセル (7, 9, 4) | ノードが持つ値 | 各ノードの値のメンバ |
| 右のセル | 次のノードのアドレス | 各ノードの `next` メンバ |

## 例 3: パイプのリングとデータページ

リングの要素と実データのページを別の領域に描き, ページ内の有効範囲を数値で示す例である.
6000 バイトを書き込み, 先頭の 1000 バイトを読み取った状態を表す.
`PgA` と `PgB` は別々に確保されたページであり, 物理アドレスが隣り合う必要はない.
上から下へ, 要素の添字が増える.

```text
head = 2, tail = 0, ring_size = 4

bufs[4]                     page          data page (4096 B)
+---------------------+     +------+      +----------+--------------+
| [0] off=1000        |---->| PgA  |----->| consumed | valid        |
|     len=3096        |     +------+      | 1000 B   | 3096 B       |
|                     |                   +----------+--------------+
+---------------------+     +------+      +--------------+----------+
| [1] off=0           |---->| PgB  |----->| valid        | unused   |
|     len=1904        |     +------+      | 1904 B       |          |
|                     |                   +--------------+----------+
+---------------------+
| [2] empty <-- head  |
+---------------------+
| [3] empty           |
+---------------------+
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `bufs[4]` | ページを指す要素の配列 | `pipe_inode_info` の `bufs` |
| `off`, `len` | ページ内の開始位置, 有効バイト数 | `pipe_buffer` の `offset`, `len` |
| `consumed`, `valid`, `unused` | 読み取り済み, 読み取り可能, 未使用の範囲 | なし |
| `head`, `tail` | 追加位置, 読み取り位置 | `pipe_inode_info` の `head`, `tail` |

## 例 4: 書き込み前後の状態変化

空のパイプへ 6000 バイトを書く操作を, 操作前と操作後の2つの図で示す.
操作では, ページ `PgA` と `PgB` を確保し, 4096 バイトと 1904 バイトをコピーする.
その後, 要素 0 と 1 に, ページへの参照と有効範囲を設定し, `head` を 2 に進める.

```text
[S2] before: head = 0, tail = 0, used = 0

src (user)          bufs[4]
+-----------+       +---------------------+
| 6000 B    |       | [0] empty <-- head  |
+-----------+       +---------------------+
                    | [1] empty           |
                    +---------------------+
                    | [2] empty           |
                    +---------------------+
                    | [3] empty           |
                    +---------------------+
```

```text
[S3] after: head = 2, tail = 0, used = 2

src (user)         pages (new)            bufs[4]
+-----------+      +----------------+     +---------------------+
| 4096 B    |=====>| PgA  4096 B    |<----| [0] off=0 len=4096  |
+-----------+      +----------------+     +---------------------+
| 1904 B    |=====>| PgB  1904 B    |<----| [1] off=0 len=1904  |
+-----------+      +----------------+     +---------------------+
                                          | [2] empty <-- head  |
                                          +---------------------+
                                          | [3] empty           |
                                          +---------------------+
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `====>` | ユーザ空間のバイト列を, ページへコピーする | `copy_page_from_iter()` |
| `<----` | 要素が, ページを参照する | `pipe_buffer` の `page` |
| `src (user)` | コピー元のユーザ空間のバッファ | `write()` の第2引数 |

## 例 5: 容量変更での配列の再確保

容量を 8192 バイトから 16384 バイトへ広げると, 要素の配列だけが新しく確保される.
要素のエントリは新しい配列へコピーされるが, ページ本体はコピーされない.
新しい配列の要素 0 と 1 は, 古い配列と同じ `PgA` と `PgB` を指す.

```text
[C0] before: ring_size = 2, head = 2, tail = 0

old bufs                      pages
+--------------------+        +----------------+
| [0] off=0 len=4096 |------->| PgA  4096 B    |
+--------------------+        +----------------+
| [1] off=0 len=1904 |------->| PgB  1904 B    |
+--------------------+        +----------------+
```

```text
[C1] after: ring_size = 4, head = 2, tail = 0

new bufs                      pages (same PgA, PgB)
+--------------------+        +----------------+
| [0] off=0 len=4096 |------->| PgA  4096 B    |
+--------------------+        +----------------+
| [1] off=0 len=1904 |------->| PgB  1904 B    |
+--------------------+        +----------------+
| [2] empty <-- head |
+--------------------+
| [3] empty          |
+--------------------+
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `old bufs`, `new bufs` | 再確保の前の配列, 後の配列 | `pipe_resize_ring()` の `pipe->bufs` と `bufs` |
| `PgA`, `PgB` | 変更の前後で同じページ | なし |

## 例 6: スラブの空きオブジェクトの管理方式

同じ4個のオブジェクトを持つスラブ `slab A` について, 空きオブジェクトの管理方式を2つ比べる.
従来方式は, 空きオブジェクト自身が次の空きを指す鎖を作る.
`sheaf` 方式は, 空きオブジェクトのポインタを配列に並べ, オブジェクトは動かさない.
どちらも `A0` と `A2` が空きで, `A1` と `A3` が使用中である.

```text
[F0] freelist: free objects form a chain

kmem_cache_cpu         slab A
+--------------+       +-----------+-----------+-----------+-----------+
| freelist ----+------>| A0 free   | A1 used   | A2 free   | A3 used   |
+--------------+       | next = A2 |           | next=NULL |           |
                       +-----------+-----------+-----------+-----------+
```

```text
[F1] sheaf: an array holds pointers to free objects

slub_percpu_sheaves    slab_sheaf (main)       slab A
+-------------+        +-----------------+     +------------+------------+
| main -------+------->| objects[0] = A0 |     | A0 free    | A1 used    |
+-------------+        | objects[1] = A2 |     +------------+------------+
                       | size = 2        |     | A2 free    | A3 used    |
                       +-----------------+     +------------+------------+
```

| 記号 | 意味 | 対応する識別子 |
|------|------|----------------|
| `freelist` | 先頭の空きオブジェクトを指すポインタ | `kmem_cache_cpu` の `freelist` |
| `next` | 次の空きオブジェクトを指す値 | 空きオブジェクト内の空きポインタ |
| `main` | 通常用の `sheaf` を指すポインタ | `slub_percpu_sheaves` の `main` |
| `objects[]` | 空きオブジェクトを指すポインタの配列 | `slab_sheaf` の `objects` |

## 検査

図は `python3 scripts/check_diagrams.py <file>` で検査する.
検査項目は, ASCII, タブ, 行末の空白, 幅, 枠の右端の位置, 識別子の定義である.
数値と本文の一致, 矢印の終点は目視で検査する.
