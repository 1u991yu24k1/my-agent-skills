# 文体と表記の規則

## 文の書き方

1. 一文には主張を一つだけ書く. 一文は60文字を目安にし, 100文字を超えない. 超えると lint が FAIL にする.
2. 述語を省略しない. 名詞を3語以上連ねない.
   体言止めで文を終えない(`〜する仕組み.`).
   文末が名詞, 記号, 英数字なら, `.` を付けても体言止めである.
   `赤ノードの子は黒.` は `赤ノードの子は, 必ず黒である.` と書く.
3. 主語を書く. 前の文と同じ主語を続ける場合と,
   命令や手順の文では省略してよい.
4. 主語に擬人化を使わない(`誰を動かすか`).
   動作主は, スケジューラ, ドライバなど実在の対象にする.
5. 指示語(`この`, `上記`, `該当`)は, 直前に指す対象が一つのときだけ使う.
   複数あるなら名詞で書く.
6. `ことで` を一文に二つ以上重ねない. 原因と結果を文で分ける.
7. 抽象名詞で済ませない.
   `整合性を担保する` ではなく, 何が何と一致するかを書く.
8. 数値, 単位, 範囲を省略しない. `速い`, `大きい` には基準を添える.

## 表記

| 項目 | 規則 |
|------|------|
| 読点, 句点 | `, ` と `. ` を使う. 引用, コード, 固有名詞は原文のまま |
| 括弧 | 日本語のかぎ括弧を使わない. 強調は `**語**` で書き, 前後に空白を1文字入れる |
| 並列 | 中黒を使わない. 地の文で ` / ` による列挙もしない |
| 英単語 | 地の文に書かず, 日本語に直す. 残すなら識別子として `` ` `` で囲む. 日本語に空白なしで接しない |
| ダッシュ | 地の文で長いダッシュを使わない. 固有名詞は除く |
| 括弧書き | 1文に1つまで. 入れ子にしない |
| 記号 | `→`, `=`, `/` を文の代わりにしない. 呼び出し経路の図示は例外 |
| 絵文字 | 使わない |
| コード | コード, パス, 識別子はバッククォートで囲み, 前後に空白を1文字入れる |

## 行の長さと改行

| 出力先 | 規則 |
|--------|------|
| 端末(会話の回答) | 1行70文字以内. 超える文は句の切れ目で折る |
| ファイル | 行長を制限しない. 一文ごとに改行する |

- 端末の制限は, 表, 引用, コードブロック, URL には適用しない.
- Markdown の改行(`<br/>` や空行)は, 段落の区切りと, リストの後だけに使う.
- 端末で呼び出し経路をインラインで示す場合は, 70文字を超えてよい.

## 列挙の形式

| 数 | 形式 |
|----|------|
| 1から2個 | 文中に書く. 同時に取りうるなら `,`, 排他なら `/` |
| 3から5個 | 箇条書き |
| 6個以上 | 表 |

表のセルには短句を入れる. 名詞を3語以上連ねず, 長文も入れない.
比較以外の目的で表を使わない. 文で書ける内容は文にする.

## コードの説明

1. コード中の語(キーワード, 変数, 関数, 構造体, マクロ)は,
   バッククォートで囲む.
2. 構造体は `struct X` ではなく `X` 構造体と書く.
3. コードブロックの前に, そのコードが何をするか,
   何を説明したいのかを書く.
4. 全体像には図を入れる. 分岐のある流れは `mermaid`,
   分岐のない呼び出し経路はインデントで書く.

## 事実の扱い

- 観測した事実, 推論, 未確認事項を区別する.
- 実行していない作業を完了形で書かない. 実行したコマンドと結果を併記する.
- 実装に言及するときは `file:line` を付ける.
- 因果関係には理由を添える. 条件付きの結論を無条件に言い切らない.
