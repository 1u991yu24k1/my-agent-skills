# 読者表と語の選び方

読者表とは, 文書を書く前に, 読者が知っていることと知らないことを5行で書いたメモである.
語を定義する範囲, 例の量, 省く内容は, すべて読者表から決める.
読者表は設計メモ(`references/document-design.md`)の一部であり, 作業用の一時ファイルにだけ書く.

## 読者表の型

読者表は, 次の5行で書く.

```
読者: <誰か> (段階: 専門家, 隣接分野の技術者, 初学者のいずれか)
既知: <定義せずに使う語と概念>
未知: <初出で定義する語>
ずれ: <読者が持ちやすい誤ったモデル>
読後: <判定できるようになること. 1から3個の疑問文>
```

パイプの内部実装を, ユーザ空間のプログラマに説明する場合は, 次のように書く.

```
読者: ユーザ空間のプログラマ (段階: 隣接分野の技術者)
既知: システムコール, ファイル記述子, ポインタ, ページ
未知: pipe_buffer, 参照カウント, リングバッファの head と tail
ずれ: write を呼ぶたびに, カーネルが新しいページを確保する
読後: 100 バイトの書き込みを2回行うと, ページはいくつ使われるか
```

読者表の各行は, 本文の次の箇所に対応する.

| 行 | 本文での使い方 |
|----|----------------|
| 読者 | 冒頭の対象読者の行 |
| 既知 | 説明を省く語の一覧 |
| 未知 | 初出で定義する語. 5語以上なら冒頭の用語表 |
| ずれ | 最も丁寧に説明する箇所 |
| 読後 | 一文要約と, 末尾の確認の問い |

## 読者の3段階

段階によって, 定義する語の範囲と例の量が変わる.

| 段階 | 定義せずに使う語 | 初出で定義する語 | 例の量 | 省く内容 |
|------|------------------|------------------|--------|----------|
| 専門家 | 分野の標準用語 | 文書内で作る語, 版に固有の識別子 | 境界例を中心に少数 | 基礎の説明, 一般論 |
| 隣接分野の技術者 | 計算機科学の一般語 | 分野に固有の語と略語 | 各節に1つ | 他分野の詳細 |
| 初学者 | 日常語 | 計算機科学の一般語を含む全語 | 概念ごとに1つ | 版差, 最適化, 例外 |

- 段階の指定がなければ, 隣接分野の技術者を既定にする.
  Linux カーネルの解説なら, ユーザ空間のプログラマを想定する.
- 計算機科学の一般語とは, ポインタ, ハッシュ表, システムコールのように, 学部の講義で扱う語を指す.
- 分野に固有の語とは, RCU, slab, TLB のように, その分野の文書でだけ使う語を指す.

## 既知の欄による冗長さの判定

既知の欄にある語と概念の説明は削る.
冗長かどうかは, この1点で判定する.
同じ語でも, 読者表が変われば説明の要否が変わる.
`copy_from_user()` の役割は, カーネル開発者には説明せず, ユーザ空間のプログラマには1文で説明する.

## ずれの欄を本文の芯にする

読者が持ちやすい誤ったモデルは, 本文で最も丁寧に説明する箇所になる.
正しいモデルを肯定文で先に書き, 誤ったモデルとの差は `>` の注意書きに置く.
上の読者表の例なら, 次のように書く.

```
`anon_pipe_write()` は, 末尾のバッファのページに空きがあれば, そのページに追記する.
空きが足りないときだけ, 新しいページを確保する.

> 書き込みのたびにページを確保するわけではない.
```

## 類推の規則

類推は, 新しい仕組みを, 読者が既に知っている仕組みに対応づける説明である.

1. 類推の相手は, 読者表の既知の欄から選ぶ.
2. 対応する点と, 異なる点を1文ずつ書く.
3. 日常の物の比喩(郵便受け, 交通整理)で説明を終えない.

```
悪い例: パイプは, 書く側と読む側をつなぐ土管である.
良い例: パイプは, ユーザ空間のリングバッファと同じく, 書き込み位置と読み取り位置を持つ配列である.
        異なる点は, 配列の要素が, データを持つページを指すことである.
```

## 読後の問いの書き方

1. 読後の問いは, 読者が何かを判定する形で書く.
   `X を理解する` は判定できないので, `100 バイトを2回書くと, ページはいくつ使われるか` のように書く.
2. 一文要約は, 読後の問いへの答えを含める.
3. 解答付きの教材では, 読後の問いを末尾の確認問題にする.

## 読者が不明なとき

1. 依頼の文面と, 文書の置き場所から段階を推定する.
2. 推定した読者を, 冒頭の対象読者の行に書く.
3. 推定によって構成が大きく変わるときだけ, 書く前に1回質問する.
