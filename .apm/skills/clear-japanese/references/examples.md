# 具体例の出し方

具体例とは, 主張を, 読者が値を追って確かめられる形にしたものである.
本ページは, 例の種類, 置き方, 大きさ, 値の選び方, 通し例, 実行例の扱いを定める.
例を置く位置は, `references/document-design.md` の抽象から具体への順序に従う.

## 例の種類

主張の性質に合わせて, 次の6種類から例を選ぶ.

| 種類 | 内容 | 使う場面 |
|------|------|----------|
| 最小例 | 値を1つずつ手で追える大きさの例 | 仕組みの説明 |
| 反例 | 仕組みが無いと起きる失敗 | 解く問題の節 |
| 通し例 | 文書全体で使い続ける1つの例 | 4節以上の文書 |
| 実行例 | コマンドと, その出力 | 手順, 観測, 検証 |
| 対比例 | 変更の前と後を同じ形式で並べる | 修正, 版差, 最適化 |
| 境界例 | 条件の端にある値 | 制約と代償の説明 |

## 置き方

1. 主張, 例, 読み取り文の順に置く. 規則を先に書いたら, 規則の直後に例を置く.
2. 読み取り文には, 例のどの値が, 主張のどの部分を示すかを書く.
3. 1節に置く例は1つにする. 2つ目の例が要るなら, 節を分ける.
4. 定義した語は, 次の段落か次の節で, 具体例の中で使う.
5. API の表は, 具体例で使った操作を並べる. 例の後に置く.

読み取り文の有無で, 例の伝わり方が変わる.

```
悪い例: (挿入の手順を示した後, そのまま次の節に進む)
良い例: 手順3で赤が連続し, 手順4の回転で高さが 3 から 2 に下がった.
        回転は, 色の規則を保ったまま木の高さを縮める操作である.
```

## 大きさ

1. 要素は3から5個, 手順は5段以内にする.
   赤黒木なら, 3要素を挿入して再着色が起きる様子を示す.
2. 例の値は, 読者が手で追える個数にする.
3. 大きな入力でだけ起きる現象は, 小さな例で仕組みを示した後に, 大きな入力の結果を実行例で添える.

## 値と名前の選び方

1. 仕組みが見える値を選ぶ.
   境界をまたぐ値(4096 に対する 4097)と, 互いに区別できる値(`0x41`, `0x42`, `0x43`)を使う.
2. 識別子は, 役割が分かる名前にする. `foo`, `bar`, `tmp` は使わない.
3. 値の単位と進数を, 1つの例の中で統一する.

## 通し例

通し例とは, 文書の冒頭で1つ決め, すべての節で同じ値と識別子を使い続ける例である.

1. 4節以上の文書は, 通し例を使う.
   パイプの解説なら, 5000 バイトの書き込み1回を, 経路, 管理構造, 状態変化の各節で追う.
2. 状態変化の図(`references/memory-layout.md`)の識別子と, 本文の識別子を同じにする.
3. 節ごとに例を変えると, 読者は節が変わるたびに前提を組み直す. 例を変えるのは, 通し例で示せない境界例に限る.

## 実行例

1. 実行したコマンドと出力だけを書く. 実行していない出力を, 想像で書かない.
2. 出力は貼り付け, 打ち直さない. 省いた行は `(省略: 12 行)` のように行数を書く.
3. 実行環境を1行で書く(`環境: Ubuntu 24.04, gcc 13.2, x86-64`).
4. 出力の後に, どの値が何を示すかを書く.

## 解答付きの教材

1. コード, 実行手順, 期待出力, 結果の読み方の4点を揃える.
2. 解答は, 期待出力の直後に書く.
3. 結果の読み方では, 出力の値と, 本文の図の状態を対応づける.
4. 末尾の確認問題には, 読者表の読後の問い(`references/reader.md`)を使う.
