# 出力前チェックリスト

出力前チェックリストは, 文書成果物を出力する前に, 上から順に確かめる項目の一覧である.
種別に固有の項目は, 各種別ファイル(`references/genres/`)の末尾にある.

## 機械検査

次のコマンドで, 表記, 骨格, 図, 抜粋をまとめて検査する.

```
python3 <skill>/scripts/check_doc.py <file> --genre <種別> [--tree <dir>]
```

- 検証記録のページには `--allow-log` を付ける.
- 端末に出す文章は `--max-width 70` を付けて検査する.
- `FAIL` はすべて修正する. `INFO` は下の項目で人手で確かめる.

## 設計

- [ ] 設計メモ(一文要約, 読者表, 6要素, 役割表)を書いてから書き始めた.
- [ ] 冒頭の段落だけで, 課題と結論が分かる.
- [ ] 骨格(見出しと各節の冒頭文)だけで, 6要素を拾える.
- [ ] 各節の冒頭文が, その節の結論になっている.
- [ ] 一文要約につながらない節を削った.
- [ ] 削除テストを行い, 主張と根拠の両方が揃っている.

## 読者

- [ ] 冒頭に, 主題の定義, 対象読者, 前提知識, 範囲がある.
- [ ] 読者表の既知の欄にある語の説明を削った.
- [ ] 読者表のずれの欄を, 本文で肯定文で説明した.
- [ ] 新語が5語以上なら, 冒頭に用語表がある.

## 構成

- [ ] H1 の主題語が, 冒頭と見出しに現れる.
- [ ] 各文が生んだ疑問に, 次の文が答えている.
- [ ] 対比と補足が, 理由より後ろにある.
- [ ] 中身のない予告文(`両者は異なる`)を, 違いを書いた文に直した.
- [ ] 見出しを, 内容を予告する名詞句にした.
- [ ] 定義より先に, 解く問題を具体的な状況で書いた.
- [ ] 性質の主張ごとに, 同じ節に根拠がある.
- [ ] 免責, 版差, 否定文を消しても読者が困らないか考え, 困らないものは削った.
- [ ] 注意書きの分量が, 本文の20%以下である.

## 例

- [ ] 各節に, 手で追える大きさの例が1つある.
- [ ] 例の後に, 例から読み取れることを書いた.
- [ ] 4節以上の文書は, 通し例を使っている.
- [ ] 実行例は実行したものだけで, 環境を書いた.

## 図

- [ ] 各図の前にリード文, 後に凡例か読み取り文がある.
- [ ] 図のラベルが, 本文と同じ表記である.
- [ ] 色, アイコン, 絵文字などの装飾を外した.
- [ ] 分岐のない流れは, 経路図か表で書いた.
- [ ] 図内の英語ラベルは語彙表にあり, 凡例表に載せた.
- [ ] 状態変化の図は, 操作前と操作後が対で, 同じ識別子と値で追える.

## 引用

- [ ] 各コードブロックの前に, 目的の説明がある.
- [ ] 抜粋は問いに答える範囲に絞り, 読む点に注釈がある.
- [ ] 注釈に, 状態, 意図, 不変条件のどれかを書いた.
- [ ] 実装の言及に `file:line` と検索語を付けた.
- [ ] 数値と主張に, 出典と条件がある.

## 用語

- [ ] INFO に出た初出の英単語を, すべて確かめた.
- [ ] 各語は, 定義されているか, 実在の識別子として書かれている.
- [ ] 造語, 作業中のあだ名, 会話にしか無い略語が残っていない.

## 文

- [ ] 体言止め, 名詞連鎖, `drop する` 型の動詞が残っていない.
- [ ] 指示語の指す先が一つに決まる.
- [ ] 否定文が3文以上続く箇所が無い. 必要なら `>` の注意書きにした.
- [ ] INFO に出た直訳語, 比喩の動詞, `の` の連続, 漢語の詰まりを確かめた.
- [ ] 文書が会話履歴や作業ログに依存していない.

## 事実

- [ ] 事実, 推論, 未確認事項が区別されている.
- [ ] 実行していない作業を完了形で書いていない.

## 読み直し

- [ ] 前提知識のない読者として1節ずつ読み, つまずいた語と文を直した.
- [ ] 別のエージェントを起動できる環境では, 初見読みの報告を受けて直した.
