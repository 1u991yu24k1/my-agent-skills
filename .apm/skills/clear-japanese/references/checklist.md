# 出力前チェックリスト

文書成果物は, 出力する前に上から順に確認する.

## 機械検査

```
python3 scripts/lint_ja.py <file>
```

検証記録のページには `--allow-log` を付ける.
実装を読む技術資料には `--profile tech` を付ける.
```` ```text ```` の図を含む文書は `python3 scripts/check_diagrams.py <file>` も実行する.

端末に出す文章は `--max-width 70` を付けて検査する.
`FAIL` はすべて修正する. `INFO` は下の項目で人手で確認する.

## 用語

- [ ] INFO に出た初出の英単語を, すべて確認した.
- [ ] 各語は, 定義されているか, 実在の識別子として書かれている.
- [ ] 造語, 作業中のあだ名, 会話にしか無い略語が残っていない.

## 構成

- [ ] 冒頭に結論(または主題の定義)がある.
- [ ] H1 の主題語が, 冒頭と見出しに現れる.
- [ ] 各文が生んだ疑問に, 次の文が答えている.
- [ ] 対比と補足が, 理由より後ろにある.
- [ ] 中身のない予告文(`両者は異なる`)が残っていない.
- [ ] 見出しが命題になっていない.

## 文

- [ ] 体言止め, 名詞連鎖, `drop する` 型の動詞が残っていない.
- [ ] 指示語の指す先が一つに決まる.
- [ ] 否定文が3文以上続く箇所が無い. 必要なら `>` の注意書きにした.
- [ ] 文書が会話履歴や作業ログに依存していない.

## 事実

- [ ] 事実, 推論, 未確認事項が区別されている.
- [ ] 実行していない作業を完了形で書いていない.
- [ ] 実装の言及に `file:line` を付けた.

## コードと図

- [ ] 各コードブロックの前に, 目的の説明がある.
- [ ] 分岐のない流れに `mermaid` を使っていない.

## 理解のしやすさ

- [ ] 冒頭に, 主題の定義, 対象読者, 前提知識, 範囲がある.
- [ ] 定義より先に, 解く問題を具体的な状況で書いた.
- [ ] 具体例を1つ, 手で追える大きさで示した.
- [ ] 性質の主張ごとに, 同じ節に根拠がある.
- [ ] 免責, 版差, 否定文を消しても読者が困らないか確認した. 困らないものは削った.
- [ ] 注意書きの分量が, 本文の20%以下である.
- [ ] 新語が5語以上なら, 冒頭に用語表がある.
- [ ] 前提知識のない読者として1節ずつ読み, つまずいた語と文を直した.

## 実装を読む技術資料

- [ ] 冒頭の1行に版と取得元がある. 本文にローカルの絶対パスが無い.
- [ ] 公開 API からの到達経路を示し, 各段階の役割と操作対象を文で書いた.
- [ ] 経路図の出典に `def`, `call`, `gen` のマーカーがある. 同じ行番号を別の箇所で繰り返していない.
- [ ] 行番号に検索語を併記した.
- [ ] 構造体は, 実際の定義を抜粋した. 省略した範囲の内容を書いた.
- [ ] 状態変化の図は, 操作前と操作後が対で, 同じ識別子と値で追える.
- [ ] 図内の英語ラベルは語彙表にあり, 凡例表に載せた.
- [ ] `後述` が, 1つの節で2回以上出ていない.
- [ ] ハンズオンに, 期待出力と結果の読み方がある.
- [ ] ソースツリーがあれば `python3 scripts/check_excerpt.py --tree <dir> <file>` を実行した.

## Obsidian のノート

- [ ] 編集前に, 既存のフォルダ, 関連ページ, 索引ページを読んだ.
- [ ] 重複するページを増やさず, 既存のページとリンクでつないだ.
- [ ] 表の中の別名付きリンクの `|` を `\|` にした.
- [ ] ページの移動や見出しの変更に合わせて, 参照元のリンクと索引を更新した.
