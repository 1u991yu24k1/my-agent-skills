日本語で書くときは, 回答を出す前に毎回この skill に従う.
形式は markdown を使う.

# 読者モデル

読者は, 今コードを開いておらず, この会話の履歴も知らない.
読者が出所を追えない語は, すべて未定義語として扱う.

# 必須規則

1. 結論から書く. 前置きと, 言い換えだけの総括は書かない.
2. 初出の語は, 定義するか, 実在の識別子をバッククォートで書く.
3. 地の文に英単語を混ぜず, 日本語で書く. 英語は `識別子` に限る.
   `drop する` のような動詞化もしない.
4. 述語を省略しない. 名詞は3語以上連ねず, 体言止めで終えない.
5. 文が生んだ疑問に, 次の文で答える. 補足と対比は理由の後に置く.
6. 見出しは内容を予告する名詞句にし, H1 の主題語を引き継ぐ.
7. 否定文は全文の10%以下にし, 連続させない. 必要な牽制は `>` の注意書きにする.
8. コードブロックの前に, その目的を書く.
9. 事実, 推論, 未確認事項を区別し, 未実行の作業を完了形で書かない.
10. 本文に作業の経緯を書かない. `指定された`, `今回`, `ユーザー指定`,
    `作業範囲`, `確認した`, `未実施` は使わない. 検証状況は別ページに分ける.
11. メモリ配置図の枠, 区画, 矢印ラベルには ASCII 文字だけを使う.
    日本語の説明は図外へ置く. 作図時は `references/memory-layout.md` を読む.
12. 解説資料は, 冒頭に定義, 対象読者, 前提知識, 範囲を書く.
    性質を主張したら, 同じ節に根拠を書く.

# 手順

1. 文書成果物なら, 書く前に下の読込表のファイルを読む.
2. 結論, 理由, 例, 補足の順に構成を決めてから書く.
   解説資料は, 読者が抱く疑問を3つ書き出してから構成する.
3. 書き終えたら `python3 scripts/lint_ja.py <file>` を実行する.
   `FAIL` はすべて直す. `INFO` は `references/checklist.md` で確認する.
   検証記録のページは `--allow-log` を付ける.
4. 解説資料は, lint の後に, 前提知識のない読者として1節ずつ読み直す.
   つまずいた語と文を直す. lint は表記しか検査しない.
5. 会話の回答は短いので, lint を省略して必須規則だけで確認してよい.

# 読込表

| 場面 | 読むファイル |
|------|--------------|
| 解説資料, 設計書 (最初に読む) | `references/explainer.md` |
| 技術用語を含む文書 | `references/terminology.md` |
| 見出しを持つ文書, 解説, 報告 | `references/structure.md` |

| 書き方に迷ったとき | `references/good_examples.md` |
| 出力の直前 | `references/checklist.md` |

# 表記の要点

- 読点と句点は `, ` と `. ` を使う. `、` と `。` は使わない.
- かぎ括弧と中黒を使わない. 強調は `**語**` で書き, 前後に空白を入れる.
- 端末への出力は1行70文字以内にし, 文の切れ目で改行する.
- ファイルへの出力は行長を制限しない. 一文ごとに改行する.
- 詳細は `references/writing_rules.md` を参照する.
