日本語で書くときは, 回答を出す前に毎回この skill に従う.
形式は markdown を使う.
本文の `<skill>` は, この SKILL.md があるディレクトリを指す.

# 読者モデル

想定する読者は, 今コードを開いておらず, 書き手とのやり取りも知らない人である.
読者が出所を追えない語は, すべて未定義語として扱う.

# 文の規則

文の規則は, 会話を含む, すべての日本語の出力に適用する.

1. 結論から書く. 前置きと, 言い換えだけの総括は書かない.
2. 初出の語は, 定義するか, 実在の識別子をバッククォートで書く.
3. 地の文に英単語を混ぜず, 日本語で書く. 英語は `識別子` に限る.
   `drop する` のような動詞化もしない.
4. 述語を省略しない. 名詞は3語以上連ねず, 体言止めで終えない.
5. 文が生んだ疑問に, 次の文で答える. 補足と対比は理由の後に置く.
6. 説明は, 主張, 仕組み, 具体例の順に書く. 具体例の後に, 例から読み取れることを書く.
7. 見出しは内容を予告する名詞句にし, H1 の主題語を引き継ぐ.
8. 否定文は全文の10%以下にし, 連続させない. 必要な牽制は `>` の注意書きにする.
9. コードブロックの前に, その目的を書く.
10. 事実, 推論, 未確認事項を区別し, 未実行の作業を完了形で書かない.
11. 本文に作業の経緯を書かない. `指定された`, `今回`, `ユーザー指定`,
    `作業範囲`, `確認した`, `未実施` は使わない. 検証状況は別ページに分ける.

# 文書の規則

文書の規則は, ファイルに書く解説, 報告, 記事に, 文の規則に加えて適用する.

1. 冒頭に, 主題の定義, 一文要約(結論), 対象読者と前提知識, 範囲を書く.
2. 節の冒頭文に, その節の結論を書く. 見出しと冒頭文だけで, 課題, 方針, 結論が読める構成にする.
3. 性質を主張したら, 同じ節に根拠を書く.
4. 図と抜粋は, 前のリード文と後の読み取り文で挟む. 図のラベルは本文と同じ表記にする.
5. 等幅の図は ASCII 文字だけで描き, 日本語の説明を図外へ置く.
6. コード抜粋には, 出典(版と `パス:行`), 読む目的, 読む点の注釈を付ける.

# 文書を書く手順

1. 作業用の一時ファイルに設計メモを書く. 設計メモは出力しない.
   設計メモは, 一文要約, 読者表, 設計の6要素(課題, 制約, 方針, 結論, 根拠, 代償), 節の役割表で構成する.
   書き方は `references/document-design.md` と `references/reader.md` に従う.
2. 下の種別表のファイルを読み, 骨格を決める. 読込表のファイルも, 場面に応じて読む.
3. 書く.
4. `python3 <skill>/scripts/check_doc.py <file> --genre <種別>` を実行する.
   `FAIL` はすべて直し, `INFO` は `references/checklist.md` で確かめる.
   ソースツリーがあれば `--tree <dir>` を, 検証記録のページには `--allow-log` を付ける.
5. 骨格読み: `check_doc.py` が表示する骨格(見出しと各節の冒頭文)を, 設計メモの6要素と照合する.
   拾えない要素があれば, 節を足すか, 冒頭文を直す.
6. 初見読み: 別のエージェントを起動できる環境なら, 本文と読者表だけを渡して読ませる.
   つまずいた語, 文, 節を報告させ, 書き直しはさせない.
   起動できなければ, 前提知識のない読者として自分で1節ずつ読む.
7. 会話の回答は, 文の規則だけで確かめてよい. 機械検査は省ける.
8. `scripts/` を変更したら `python3 <skill>/scripts/test_lint.py` を実行する.

# 既存の文書を直すとき

他の書き手やエージェントの文書を直すときは, 主張, 比重, 言い切りの強さ, 文の働き(説明, 依頼, 決まり)を保つ.
原文と資料にない事実を足さない. 意味が1つに決まらない箇所は, 直さずに書き手へ質問する.

# 表記の要点

- 読点にはカンマと空白, 句点にはピリオドと空白を使う. `、` と `。` は使わない.
- かぎ括弧と中黒を使わない. 強調は `**語**` で書き, 前後に空白を入れる.
- 端末への出力は1行70文字以内にし, 文の切れ目で改行する.
- ファイルへの出力は行長を制限しない. 一文ごとに改行する.
- 詳細は `references/writing_rules.md` を参照する.
